## 3. What is complete, and what each piece contributes

### 3.1 M0: Foundation (Phase 0)

| Completed | Where | What it contributes |
|---|---|---|
| Typed configuration with validation | `internal/platform/config` | Every service reads its settings the same way and fails fast on bad values |
| Structured JSON logging with request IDs | `internal/platform/logging` | Any request can be followed through the logs |
| HTTP toolkit: router with route labels, middleware chain, RFC 9457 errors, strict JSON, graceful shutdown, admin router | `internal/platform/httpx` | Services share one safe HTTP stack; errors have stable codes; internal endpoints stay off the public port |
| Health checks with draining (`/livez`, `/readyz`) | `internal/platform/health` | Pods stop receiving traffic before shutdown, so in-flight requests finish |
| Prometheus metrics registry | `internal/platform/metrics` | The data behind dashboards, alerts and published numbers |
| Ed25519 admission tokens with key rotation | `internal/platform/authn` | Only admitted buyers can hold seats; keys rotate without downtime |
| PostgreSQL pool and embedded migration runner (advisory lock, checksums) | `internal/platform/postgres`, `db/migrations` | Schema changes are applied safely and applied migrations can't be edited |
| Valkey client | `internal/platform/valkey` | Connection to the hot-path store, Sentinel-ready for Phase 5 |
| Component lifecycle and build info | `internal/platform/app`, `buildinfo` | Clean start and stop for every service; every binary reports its version |
| Makefile, `compose.yaml`, Dockerfile, GitHub Actions CI, golangci-lint, pre-commit hooks, migration check script | Repository root, `.github/`, `scripts/` | One-command local stack; every push is linted, tested and checked by E1 |
| `README.md`, `AGENTS.md`, `CONTRIBUTING.md`, `docs/architecture.md`, ADRs 0001 and 0003 | Repository root, `docs/` | New contributors and AI agents know the rules and the system map |
